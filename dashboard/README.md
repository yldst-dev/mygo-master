# Dashboard

MyGo로 만든 네이티브 대시보드. 웹뷰, HTML, JavaScript 없이 `ui.View` 로만 그립니다

한국어 · [English](README.en.md)

</div>

지표 카드 4개, 월별 매출 그래프, 분류별 매출 도넛, 최근 주문 표로 "이번 달은 어떤가"에 답하는 화면입니다. 참고 이미지를 보고 만들었고, 버튼과 메뉴와 그래프에 모두 호버와 움직임이 들어 있습니다. 화면의 주문과 고객은 지어낸 예제 데이터입니다.

## 실행하기

Go가 필요합니다. `go.mod` 는 Go 1.27.3을 요구하고, 설치된 Go가 더 낮아도 기본 설정(`GOTOOLCHAIN=auto`)이면 Go가 그 버전을 내려받습니다.

```sh
go tool mygo dev
go test ./...
go tool mygo build -skip-dmg
```

`go tool mygo dev` 는 Go 파일을 고치면 다시 빌드하고 재시작합니다. 빌드 결과는 `build/darwin-arm64/Dashboard.app` 에 생깁니다. 기본 창은 1440×900이고 최소 창은 1024×680입니다.

## 화면

| 화면 | 내용 |
|---|---|
| Dashboard | 지표 4개와 미니 그래프, 월 선택 알약이 달린 매출 그래프, 도넛, 최근 주문 5개 |
| Analytics | 매출 그래프와 월별 지표 표 |
| Orders | 검색창으로 거르는 전체 주문 |
| Customers | 주문을 고객별로 묶은 요약 |
| Settings | 다크 모드 스위치 |

상단 막대의 검색창은 주문 번호, 고객, 상태, 날짜로 거릅니다. 알림 벨과 사이드바 아래의 계정 메뉴는 키보드로도 열고 닫습니다.

## 파일

| 파일 | 맡은 일 |
|---|---|
| `main.go` | 앱을 만들고 창을 띄운다 |
| `shell.go` | 앱 상태, 내비와 계정 메뉴와 알림 항목. 부품에 앱 상태를 잇는 얇은 층 |
| `pages.go` | 페이지 5개. 부품에 예제 데이터를 넘긴다 |
| `components.go` | 앱 상태에 묶이지 않는 부품: 카드, 상태 알약, 표, 드롭다운 메뉴, 세그먼트, 검색칸, 테마 스위치, 지표 카드와 증감 배지, 단추와 링크 |
| `charts.go` | 미니 그래프, 월별 영역 그래프, 도넛, 그래프 말풍선 |
| `frame.go` | 사이드바(미끄러지는 내비 알약, 계정 메뉴), 상단 막대, 알림 벨, 페이지 틀 |
| `formats.go` | 금액, 비율, 천 단위 서식 |
| `window.go` | 타이틀바를 숨기고 기본 크기와 최소 크기를 정한 창 옵션 |
| `data.go` | 예제 데이터, 주문 거르기와 고객 요약 |
| `palette.go` | 역할별 색(라이트, 다크)과 테마 전환. 스킬의 시작 템플릿과 같은 파일 |
| `motion.go` | 모션 값 이름, 벨 키프레임, `progress`, `pressable`. 시작 템플릿의 값 목록에서 이 앱이 쓰는 줄만 남긴 것 |
| `icons.go`, `icons/` | [Lucide](https://lucide.dev) 아이콘 15개(ISC 라이선스) |
| `main_test.go` | 앱 전체를 창 없이 도는 테스트 |
| `palette_test.go`, `components_test.go`, `charts_test.go`, `frame_test.go`, `formats_test.go`, `icons_test.go`, `window_test.go`, `targets_test.go` | 팔레트와 부품을 따로 시험하는 테스트. 부품만으로 화면 하나를 조립하는 시험도 있다 |
| `mygo.json`, `resources/` | 앱 이름과 식별자, 아이콘 |

패키지는 하나입니다. 클린 아키텍처 규칙을 정하기 전에 만든 앱이라 층을 나누지 않았습니다. 새 앱의 구조는 스킬의 시작 템플릿을 보십시오.

## 디자인

방향은 차분한 업무 도구입니다. 덜어 내고 맞춰서 세련되게 만듭니다.

- 푸른 기가 도는 밝은 회색 바탕에 강조색은 파랑(`#0A5FFE`) 하나입니다. 다크 모드는 뒤집은 값이 아니라 역할마다 다시 고른 값입니다.
- 글자색은 제목, 라벨, 보조 세 단계입니다. 카드는 모서리 16, 1 DIP 선, 아주 옅은 그림자로 구분합니다.
- 누를 수 있는 것은 모두 28×28 DIP 이상이고 `TestEveryTargetIsLargeEnough` 가 지킵니다. 메뉴를 열었을 때와 검색어를 넣었을 때도 잽니다.
- 모든 상태 변화가 움직입니다. 호버 120ms, 누름 100ms, 색 전환 200ms, 그래프 표식 스프링 180ms, 알약과 숫자 굴림 스프링 240ms입니다. 움직임이 끝나면 프레임 요청도 멈춥니다.
- 시스템이 움직임을 줄이라고 하면 끝값으로 바로 갑니다.

색, 글자, 간격, 모서리, 누를 곳의 크기와 모션 값의 근거는 스킬 `mygo-master` 의 `references/design.md` 와 `references/motion.md` 에 있습니다.

## 테스트

`go test ./...` 는 창 없이 `ui.Tester` 로 돕니다. 화면의 숫자와 글자, 월 선택, 검색, 페이지 이동, 다크 모드, 메뉴의 키 조작, 그래프와 도넛의 호버, 말풍선이 그래프 안에 머무는지, 움직임이 끝나는지, 줄인 움직임, 누를 곳의 크기, 팔레트의 모든 색이 함께 섞이는지와 글자 대비를 확인합니다. 부품(카드, 메뉴, 세그먼트, 표, 검색칸, 스위치, 지표 카드, 그래프, 도넛, 사이드바, 상단 막대, 알림 벨, 페이지 틀, 창 옵션)은 부품만으로 만든 작은 화면에서도 따로 시험하고, 부품만으로 화면 하나를 조립하는 시험도 있습니다.

## 알려진 한계

- 다크 모드에서 월 선택 알약과 메뉴 강조 행의 흰 글자 대비가 3.84:1로 4.5:1에 못 미칩니다. `palette.go` 의 `accentFill` 로 칠하면 4.66:1이 되지만, 화면이 조금 달라져 아직 바꾸지 않았습니다.
- 라이트 모드 아바타의 글자 대비가 4.27:1입니다.
- 앱 아이콘은 `mygo init` 이 만드는 기본 아이콘 그대로입니다.
- macOS에서만 실행해 봤습니다.
